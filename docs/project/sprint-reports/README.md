# Comptes rendus de sprint

Un compte rendu **par sprint de 2 semaines** (calendrier S01 à S17 : `docs/jira/PLAYBOOK.md` §2), rédigé le dernier jour du sprint (revue + rétrospective). Ce sont les « comptes rendus d'exécution » exigés par le Bloc 1 (C1.5) et la source des relevés de KPI à deux dates (C1.6).

## Nommage
`sprint-01.md`, `sprint-02.md`, ... (copier `template.md`). Un fichier = un sprint.

## Règles
1. Écrire avec des **faits mesurables** : tickets terminés / prévus, heures réelles vs prévues, KPI relevés, démos réalisées.
2. Consigner **les écarts réels** (aussi dans `../deviation-journal.md`) et les décisions (aussi dans `../decision-log.md`).
3. Mettre à jour `../risk-register.md` à chaque sprint.
4. Communication au commanditaire : l'équipe pédagogique joue le rôle de BeeAfrica en revue de sprint ; noter ses retours.
5. Aucune donnée personnelle ni secret.
